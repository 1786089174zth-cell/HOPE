# 独立版 SuperMimic（`supermimic_hope/core/`）——四动作任务

日期：2026-11-16（America/Los_Angeles）。按论文 arXiv 2610.28480 和官方代码
[dongc1/supermimic](https://github.com/dongc1/supermimic)（7e94b07，Apache-2.0）重新实现。
训练时不启动 Isaac：物理是纯 MuJoCo-Warp，任务由仓库里的数据资产独立重建。

**目前验证到 6000 次迭代（约 53 分钟训练，一个种子）。没有跑完整的 30000 次迭代，没有 Gate3，没有实机。**

## 1. 和论文 / 官方代码一致的部分

| 项 | 取值 |
|---|---|
| 循环 | 采集 → 拟合动力学 → BPTT 改进策略，每次迭代各一次；UTD 0.4（每次迭代 2.5 个向量步） |
| 动力学 | MLP 2048×3（LayerNorm、GELU）；输入去航向状态 `[z, g_b, v_b, w_b, q, qd]`、执行的 PD 目标、仿真上下文；输出 `[Δv_b, Δw_b, Δqd]`，位姿解析积分（`substep_coeff = 5/8`） |
| 动力学损失 | 8 步自回归窗口，10 批 × 2048 窗；Bryson 权重（根位置 0.01、根姿态 0.02、关节 0.1、关节速度 3.14）；Adam 2e-4，梯度范数 1.0 |
| 想象 | 从回放状态出发 32 步；软生存权重 `c ← c(1−d̂)`；末端 critic 自举并截到 `r_max/(1−γ)`；γ 0.99 |
| 策略优化 | Adam 2e-4，β=(0.9, 0.95)；梯度范数 1.0 后逐元素 0.1 |
| critic | MLP 256-128，只用想象轨迹的 GAE(0.95) 目标，5 轮 × 4 小批，无目标网络 |
| 软终止 | `sigmoid((归一化误差 − 1)/0.05)`；根高度偏离参考 0.25 m 或倾斜（重力 z 分量）偏离 0.8 |
| 跟踪奖励 | 表 A.2：根位置/姿态各 0.5，身体位置/姿态/线速度/角速度各 1.0，动作变化率 −0.1，关节限位 −2 |
| 采集噪声 | 每个动作维 N(0, 0.1²)（表 A.5；官方代码最新提交已去掉，`action_noise=0` 可关） |
| 回放 | 每环境 1000 步；学习率余弦衰减到 0.03×（25 万次迭代） |
| 加速 | 动力学更新和策略更新各录成一个 CUDA graph 重放（官方 `CapturedUpdate` 的做法） |

和官方代码的差别：优化器全部用 Adam（官方隐藏层用 Muon，需要更新的 PyTorch）；策略批量默认 2048
（论文 4096，在 24 GB 显卡上和 1000 步回放放不下）；没有按回报的复位采样（题目是题库抽样，不是固定动作库时间轴）；
单一目标接口，所以没有多编码器和潜变量。

## 2. 任务：从 Isaac 任务的数据和时钟重建

数据：`assets/wide_stroke_v26_urdf2_plane058_20261110`（四段示范、题库、右臂适配器）。

- **出题**：只用有合格示范的 543,395 行；四类各 25%；35% 来自部署平面薄层 x 0.50–0.58 m，其余在该类题池里均匀抽。
- **参考动作**：该类示范按任务的准备段时间扭曲播放（剩余时间 ≤ 最短准备时间 T 时才开始动，把 L 秒的准备压进 T 秒），
  右臂 7 个关节叠加该题的适配器（三次 Hermite 包络，击球时刻等于 `delta_q / delta_dq`）。
  实测：击球帧上参考球拍对目标的误差，四类都在 1 cm、0.012 m/s、4° 以内。
- **回合时钟**：开局 HOLD（站姿开局 4–6 s，15% 为 10–20 s）→ 通知 → 示范第 60 帧击球 → 回位；
  击球后 0.5 s 起可来下一球（25% 立即，否则 0–1.6 s，50% 改为 2.5–5.5 s）。
- **观测**：部署用的 110 维 `hitter_pure` 帧，策略输入最近 10 帧（旧在前）。陀螺 ±0.2、关节位置 ±0.01、关节速度 ±0.5；
  动捕位置每回合偏置（5/5/3 mm）加白噪声（3/3/5 mm），姿态同理；目标位置每题偏置 3 mm 加白噪声 3 mm。
  开局 HOLD 期间看到的是任务的空闲包（`tts = 1.2`、正手框中心）。
- **动作**：`q_des = q0 + scale·a`，夹到软限位，头部两关节被动；`q0` 含每环境 ±0.01 rad 的编码器偏置；
  奇数环境每回合 50% 概率带 1 拍指令 FIFO。
- **复位**：25% 默认站姿（离站位 3–10 cm、偏航 ±0.3），其余从参考状态出发（一半在通知时刻，一半在挥拍中段），
  加小的位姿/关节噪声。
- **任务奖励**（接口自己的奖励，论文附录 B 的做法）：击球窗 ±0.12 s 内，球拍在移动接触路径上的位置（权重 2，std 0.10 m）、
  球拍速度（2，std 0.6 m/s）、拍面法向（1，std 0.3）。

**没有照搬 Isaac 任务的地方**（都是有意的简化，部署前要评估）：

- 没有指令到达的子步相位随机化（0–15 ms）；没有动捕延迟、丢包和突发中断；目标噪声没有 AR(1) 分量和 1 拍延迟。
- 没有周期性推力（论文认为确定性世界模型学不了状态跳变，也没有用）。
- 没有挥拍后状态回放复位；没有课程（题库难度一开始就全开）。
- 奖励是论文的跟踪奖励加击球项，不是 PPO 配方的 40 项。HOLD 姿态达标、步法、防搓地、回位稳定这些 Isaac 评测判据没有对应的奖励项，也没有测。
- 质量随机化是整机一个系数（Isaac 是每个连杆独立 ±15%）。
- 物理只有 MuJoCo-Warp。Gate3 用的是同一份 MJCF，但 Isaac/PhysX 上的表现没有测。

## 3. 验证

- 可微正运动学对 MuJoCo：位置、姿态、角速度、线速度最大误差 1e-7（32 个刚体，20 组随机状态）。
- 示范与 MJCF 一致：四段示范的关节顺序、32 个刚体位置与正运动学完全吻合。
- 参考状态对自身的奖励 = 上限 10/s，终止误差 0。
- CPU 单元测试 `tests/test_core.py`：9 项通过（积分一致性、航向不变、Bryson 损失、适配器包络、终止阈值、回放窗口与历史、GAE、学习率）。
- 全尺寸速度（RTX 4090，4096 环境，策略批量 2048）：1.89 次迭代/秒（采集 0.06 s、动力学 0.18 s、策略 0.27 s），显存约 17 GB。
  Isaac 管理器版是 0.46 次迭代/秒。
- 训练日志（seed 0，从零开始，带 0.1 动作噪声的原始策略，50 次迭代平均）：

| 迭代 | 奖励 /s（上限 10） | 每步跌倒 | 综合命中 | 位置误差 | 速度误差 | 法向误差 |
|---:|---:|---:|---:|---:|---:|---:|
| 200（只训动力学） | 2.75 | 1.0% | 0 | 0.66 m | 2.6 m/s | 80° |
| 800 | 4.08 | 0.02% | 0 | 0.49 m | 2.6 m/s | 82° |
| 1600 | 4.69 | 0 | 0.8% | 0.16 m | 1.6 m/s | 36° |

  综合命中 = 击球那一拍球拍位置 < 7.5 cm、速度 < 0.5 m/s、法向 < 15° 同时成立（任务的 exact-strike composite 判据）。
  第 800 次迭代之后想象奖励与真实奖励相差 < 0.1/s（刚开始更新策略时相差 0.3–0.4），8 步动力学误差降到 0.0011 rad。
  换种子（seed 1）和换成当前代码重跑 seed 0，2400 次迭代处的日志命中率是 0.25–0.27，同一量级。
- 续训和 ONNX 导出（与 PyTorch 输出相差 2e-6）各跑通。

### 3.1 评估方法（`evaluate.py` 的默认设置）

1024 环境 × 3000 步（约 16,000 次击球），确定性策略，传感器噪声保留，种子 12345。两点必须固定，否则数字不可比：

- **评估时冻结归一化统计量。** 最初的评估在滚动时还在更新 actor 的观测归一化，同一个策略的命中率在 4000 步内从 0.78 滑到 0.60；
  冻结后同一区间稳定在 0.76–0.80。部署的 ONNX 里归一化本来就是固定的，所以冻结后的数字才对应部署。
  （训练中归一化统计量在 1e8 个样本后停止更新，与官方实现一致，约在第 9,700 次迭代。）
- **不含"挥拍中段开局"。** 训练的复位有一半把机器人放在参考动作的挥拍中段，这种开局的第一拍更容易打中；评估里关掉。

同一检查点换评估种子（777），综合命中 0.774 对 0.785，相差约 0.01。

### 3.2 相邻检查点的击球能力大幅摆动，必须用滑动平均权重

训练日志的命中率是 50 次迭代的平均，看不出单个检查点的好坏。同一条训练里逐个评估（1000 步，约 5,200 次击球）：

| 检查点 | 原始权重 | 四类（站正 / 站反 / 迈正 / 迈反） | 滑动平均权重 | 四类 |
|---:|---:|---|---:|---|
| 2700 | 0.05 | 0.05 / 0.08 / 0.03 / 0.05 | 0.48 | 0.32 / 0.55 / 0.52 / 0.54 |
| 2800 | 0.15 | 0.13 / 0.20 / 0.15 / 0.12 | 0.49 | 0.32 / 0.53 / 0.56 / 0.55 |
| 2900 | 0.53 | 0.57 / 0.63 / 0.44 / 0.46 | 0.49 | 0.37 / 0.53 / 0.54 / 0.54 |
| 3000 | 0.03 | 0.01 / 0.06 / 0.00 / 0.05 | 0.52 | 0.41 / 0.52 / 0.59 / 0.55 |

原始权重在 0.03–0.53 之间跳；滑动平均（每次策略更新衰减 0.99）是 0.48–0.52，并随训练上升。第 6000 次迭代也一样：原始 0.30，滑动平均 0.785。
两个从零训练到 2500 的检查点（seed 0、seed 1）原始权重评估只有 0.03 和 0.08，而它们的训练日志是 0.3。
原因没有进一步定位（可能是 2e-4 的学习率下单步更新对击球那一拍的精度影响太大）；滑动平均不改变训练过程，
只改变拿去评估和导出的权重。每个检查点同时存 `actor`（原始）和 `actor_ema`，`evaluate.py`、`export.py` 默认用后者。

### 3.4 击球回归检查

任何对任务、奖励、学习器的改动，采用前要和基线比：两个版本训练到同一迭代数，用 `evaluate.py` 的默认设置评估，然后

```bash
/opt/drone_venv/bin/python tools/check_hitting.py <候选 evaluation.json> docs/baselines/hitting_6000_seed0.json
```

综合命中、位置通过率、虚拟击球率和四类各自的命中率，任何一项比基线低 0.05 以上，或击球误差高 15% 以上，或跌倒率上升，就判失败（退出码 1）；
两份评估的设置（步数、环境数、种子、是否滑动平均等）不同则拒绝比较（退出码 2）。
`docs/baselines/hitting_6000_seed0.json` 是上表第 6000 次迭代那一行。评估种子带来的差异约 0.01；
训练种子之间的差异在 6000 次迭代处没有量过，所以 0.05 的容差是暂定值。
