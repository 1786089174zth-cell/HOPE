## 1. 0.58 平面上球为什么到不了目标

`tools/gate3/returns.py` 对每个球取来球速度和旋转、规划器指令的拍速、策略实际的拍速和拍面，
过一遍仿真器自己的击球模型和飞行模型（用实际挥拍重建的出球速度与仿真器记录的只差 0.04–0.06 m/s）。

- 45000 在 0.58 平面上：拍速误差只有 ±0.2 m/s，但拍面系统性偏——正手偏左约 10°（球落到目标左边 0.55 m），
  反手偏右 9–10°（右边 0.3–0.45 m），另外偏开 5–14°。42000 也一样（13.5°）。
- 同一批策略在 0.465 平面上拍面只偏 3.5–4.4°。0.525 平面是 7.0°：击球面越靠前越差。
- 训练仿真里原来的"命中"只要求拍面误差小于 15°，所以命中率 0.99 看不出问题。
  新指标 `task/landing_err_m`：45000 是 0.22 m，只有 52% 的球落在指令落点 0.2 m 以内。

## 2. 分界球

策略的 110 维观测里没有"正手还是反手"，只能从球的左右位置判断。题库里四个动作的左右范围不重叠
（迈步正手 | −0.58 | 站立正手 | −0.275 | 站立反手 | 0.10 | 迈步反手），但 ±2 cm 的目标随机偏移会让每条分界线两侧
同一个位置既被标成正手又被标成反手，策略在那里学成了两种动作的混合：仿真里把题出在分界附近，拍面误差平均 28–50°。
Gate3 里哪个落点贴着分界线（0.465 平面是工位右 0.26 m，0.58 平面是 0.296 m），哪个就丢 5–9 个（共 15–20 个），回球方向偏 12–44°。

## 3. 改动（`core/task.py`，都已是默认值）

- `landing=2.0`：执行出来的挥拍经击球模型（`paddle_contact`）和飞行模型（`flight_landing`）得到的落点，
  对指令挥拍的落点，双高斯 0.40 / 0.12 m。
- `return_velocity=1.0`：球离拍速度的双高斯，0.5 / 0.15 m/s。
- 击球位置和拍面的窄高斯收紧：位置 3 → 2 cm，拍面 0.3 / 0.1 rad → 0.2 / 0.06 rad。
- `side_consistent=True`：随机偏移不许把目标推过所属动作的左右边界；`edge_probability=0.15`：正反手分界两侧多出题。
- `plane_probability=0.6`、`plane_x=(0.555, 0.58)`：六成的题在 0.58 击球面。
- `feet_flat=0.5`、`station=0.5`、`feet_station=0.5`、`heading=0.5`（0.08 rad）：见 `rally_20261118.md`。

训练仿真（确定性策略，标准出题，旧物理），对 42000：命中率 0.993 → 0.989，拍面误差 5.7° → 4.6°，
**击球位置误差 2.0 → 2.3 cm（`check_hitting` 判为退步）**。落点误差对 45000（新物理）：0.22 → 0.14 m，落在指令落点 0.2 m 以内的球 52% → 79%。Gate3 里触球点离拍心：0.58 平面平均 1.9 cm，0.465 平面 1.3 cm。

其他：100 球里骨盆前后漂移 ±0.3 cm，转向平均 2.6°（最大 6.0°）；左脚最大翘角 4.8°；进场躯干侧倾 +0.2° – +0.4°、脚距 0.43 m。

## 3b. 随机推与 0.58 平面的低球：`logs/supermimic/2026-11-19_15-36-52_ft15_push_lowplane/model_54000.pt`

`push_rate=0.12`（每个环境约每 8 s 一次根速度突变，水平最大 0.4 m/s、竖直 0.1 m/s、绕竖轴 0.3 rad/s；
被推的那一拍在回放里作为窗口边界，不进世界模型的训练对）和 `low_on_plane=0.5`（一半的低球题移到 0.58 击球面）。
此前的随机化只有每环境的脚底摩擦（0.3–1.6）、整机质量 ×0.85–1.15、躯干质心偏移、PD 增益 ×0.85–1.15，没有推。

## 3c. 机器人站在桌沿后 0.58 m、在桌沿处击球：`logs/supermimic/2026-11-19_18-58-17_ft17_station058/model_59000.pt`

用户要的摆法：工位（HOME）在桌沿后 0.58 m，击球面仍是工位前 0.58 m，所以击球点就在桌沿 x = 0 上方。
Gate3 的 `run_gate3.py` 现在接受场景里的 `station_x: -0.58`（只认 −0.50 和 −0.58），`pp_gate3_rally.sh` 的几何检查
相应接受（站 −0.58，击球 0）这一对；默认行为不变。场景：`tools/gate3/scenarios/fixed-home-station058.yaml`、
`ball_paths_station058.yaml`（`make_scenario.py --strike-x 0.0 --station-x -0.58`）。标准球到击球面时高 0.90–0.92 m。

从 54000 续训 5000 次迭代：`table_edge_x=0.58`（训练里的桌沿按新站位放）、`plane_shift=0.5`（一半非击球面题移到击球面）、
`racket_position=3.0`、`feet_heading=0.5`、`immediate_probability=0.35`。这些现在是默认值。

54000 在这个摆法下打偏拍心，是因为训练里桌沿一直在工位前 0.50 m，策略把拍子抬高躲一张不存在的桌子。
仿真（新物理）：带随机推命中率 0.971（54000：0.952），击球面低球 0.952（0.813），`check_hitting` 对 42000 PASS。
多球路唯一真丢的一个是中快球落在 x = 2.724 m，越过远端 4 mm。落点的系统偏差（偏远 0.12–0.13 m）里 0.10 m 是规划器指令本身的残差。

**Gate3 球报告的另一个坑**：台面反弹的判定高度容差按测得的观测延迟（约 1 ms）算，而仿真器的反弹采样可能晚一个物理步，
最高那档（桌面上 29.9 mm）会以约 1 mm 之差被判非法——发球反弹被拒，这球就算"没碰到"；回球反弹被拒，合法回球就算不合法。
约每 100 球一次，与策略无关。`tools/gate3/rejudge.py` 按至少一个物理步（4 ms）的延迟重判，`summarize.py` 和 `by_serve.py`
已经用它（报告的原始计数另存为 `report_*`）。重判后改变的历史结果：42000 0.465 平面第二轮 99 → 100，49000 第二、三轮 99 → 100、95 → 96，
49000 0.58 平面 99、98 → 100、100，54000 0.58 平面 99 → 100，52000 98 → 99 等。

## 4. 没解决的

- **0.58 平面上的低球打不到**：0.84 m 的球在桌面上方只有 8 cm，球拍半径 8.5 cm。这类短而低的球需要规划器换击球点。
- **0.58 平面让通知更短**：击球早了约 0.1 s，规划器 commit 的时机没变（落台后约 0.1 s），标准球的通知从 0.51 s 变成 0.39–0.43 s。
  49000 没练过这么短的通知也能打（通知 0.30–0.38 s 的中高球 41/41）；专门加短通知题的 52000 反而更差（24/39）。
  `rush_probability` 仍默认关闭。
- 拍面在 0.58 平面上仍偏开约 4.5°；转向漂移没有根除。
- **0.58 击球面是改部署包元数据得到的**（`tools/gate3/shift_strike_plane.py <包> 0.56 0.60`）。Isaac 任务导出的击球框是 0.35–0.58，
  Runner 取中点 0.465。正式采用需要在任务定义里改。
- Gate3 的球报告有一个坑：一个没人回的球停在台上不消失，之后所有球的 `contact_pass / landing_pass` 都被判成假
  （"telemetry incomplete"）。`tools/gate3/by_serve.py` 现在对这些球直接按记录到的触拍和落台事件判；`summarize.py` 没有改。
- 每个结论的样本：连发每个配置 2–3 轮，多球路 2 轮；续训单种子。
