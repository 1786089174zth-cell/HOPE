# SuperMimic v3: PPO-anchored world-model training — 2026-10-24

## Why v1/v2 did not learn

Evidence: run `7769htug` (v1, 3281 iterations), the v2 800-iteration
validation (`analysis/supermimic_stall_20261024/repair_hybrid_6144_kl_01`) and
two PPO runs of the same machinery at 6144 environments
(`logs/rsl_rl/agibot_a3_hitter_pingpong/2026-10-19_22-49-36_stationary_reach_v4_scratch`,
`2026-10-22_05-16-33_stationary_reach_ppq004_generalization_scratch`).

1. **3000 SuperMimic iterations are only ~130 PPO updates of data.** UTD 0.4
   collects 2.5 vector steps per iteration: v1 reached 8237 vector steps at
   iteration 3281. PPO collects 64 per update. In the PPO runs, update 130
   still had 40-44-step episodes and a 0.003-0.006 virtual hit rate; survival
   jumped at update ~200 (330-370 steps), hit rate was 0.14-0.21 at update 500
   and 0.46-0.52 at update 1000 (64k vector steps). Zero hits at v1 iteration
   3000 is therefore expected even for PPO. v2 should be judged the same way.
2. **The environment step, not physics, sets throughput.** Collection costs
   ~160 ms per vector step with MuJoCo-Warp, the same as PhysX (manager,
   reward and telemetry overhead). v2 spent 0.40 s collecting 2.5 steps and
   0.37 s learning per iteration: ~20k real samples/s against PPO's ~33k.
   SuperMimic's upstream speedup assumes nearly free simulation.
3. **v2's real-data update was an order of magnitude weaker than PPO's.**
   Fixed exploration std 0.1 (PPO learns 0.30 within [0.05, 0.35]); one 16k
   minibatch per iteration (PPO: 80 minibatches of 24.6k per update); fixed
   2e-4 learning rate; a KL penalty toward behavior up to six iterations old.
   Over 600 actor updates the clip fraction stayed at 21% and the mean episode
   moved from 1.26 s to 1.38 s; the policy did not improve.
4. **The model gradient has no analytic reward.** Upstream differentiates
   BeyondMimic's analytic tracking reward through predicted body states. Here
   all non-terminal reward (39 stateful HOPE terms) is one learned scalar head;
   v1's pure model-driven updates regressed (episodes 1.27 s -> 0.50 s).
5. **Imagined step size.** With this actor, one Adam step at upstream's 2e-4
   moved the policy by a mean Gaussian KL of ~0.06, six times PPO's target for a
   whole update (smoke test below).
6. **Action feedback.** v2 clamped actions before the environment, so the
   actor observed clamped previous actions; `train.py` and the deploy runner
   feed back the raw actor output (heads zeroed). v3 sends raw actions.

## v3 design

- Each iteration collects one PPO rollout (`algo.runner.num_steps_per_env`,
  64) with the policy and `ProjectionPPO` built exactly as `train.py` builds
  them, including the runner's random episode-clock initialization, then runs
  the unmodified PPO update.
- The world models (unchanged heads, failure margins and contracts) fit
  `wm_batches=16` replay windows per iteration. Replay no longer stores `s1`;
  it is reconstructed from the next row, which saves 1.4 GB at 6144 x 128.
- From iteration `wm_only_iterations=20`, up to `bptt_steps=4` imagined actor
  steps run from the latest rollout, bootstrapped by the PPO critic. A step
  whose KL from the post-PPO policy exceeds `bptt_max_kl=0.005` is undone; the
  step size (initial 5e-5) adapts within [1e-6, 1e-3] like PPO's schedule.
- `supermimic.bptt_steps=0` is plain PPO on Warp physics for A/B comparison.
- Collection still verifies failure margins and the termination-cost
  decomposition every step, and now also that the real action feedback equals
  the action sent (`Replay/real_action_feedback_max_abs_error`).

## Validation

- 21 unit tests pass (plus the MJCF test with the isolated MuJoCo deps), with
  new cases for exact `s1` reconstruction across ring wraparound, undoing an
  over-budget imagined step, and the frozen PPO critic during imagination.
- 256 environments, 3 iterations (`analysis/supermimic_v3_20261024/smoke_256`):
  completed and saved. One imagined Adam step at 2e-4 gave KL 0.057.
- 6144 environments, batch 2048, 8 iterations, imagination from iteration 2,
  W&B offline (`analysis/supermimic_v3_20261024/full_6144`): completed and
  saved `model_4.pt`/`model_8.pt`. Iteration 13.5-14.1 s: collection 10.7-11.5 s,
  PPO 1.7-1.9 s, world model 0.55-0.60 s, imagination 0.27 s. Device memory in
  use 9.68 GiB, torch peak 3.63 GiB. Real and modeled action-feedback errors
  were exactly 0. After two rejected steps the imagined step size settled and
  4/4 steps were accepted at KL 0.004-0.005. PPO's adaptive rate dropped on the
  first update (normalizer warm-up, as in `train.py`) and recovered.
- `model_state_dict` has exactly the keys and shapes of a `train.py` PPO
  checkpoint (`stationary_reach_ppq004_generalization_scratch/model_10000.pt`).

Eight iterations say nothing about learning speed. Judge a run by real steps
against the PPO calibration above: survival should jump by iteration ~200 and
hits should appear by ~500. Run `supermimic.bptt_steps=0` as the A/B baseline
to see whether the model gradient helps.

Task convergence, physics parity and hardware behavior are `NOT_PROVEN`.
