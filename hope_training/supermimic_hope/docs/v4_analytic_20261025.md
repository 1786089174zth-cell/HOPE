# SuperMimic v4: analytic HOPE heads — 2026-10-25

v1–v3 learned the reward as a scalar network head. Its gradient with respect to
the action is uninformative, which is why v1 regressed and v2/v3 had to lean on
real-data policy gradients. Upstream SuperMimic instead differentiates an
analytic reward of the predicted physical state. v4 does the same for HOPE.

## Components

| Piece | File | Verified by |
|---|---|---|
| Torch FK of the Gate3 MJCF (link and COM pose/velocity, racket mount) | `analytic/kinematics.py` | MuJoCo `mj_forward` unit test; Warp `robot.data` max error 1.7e-5 (velocities), 2.9e-6 m (positions) |
| Three per-step states, controls and recorded context | `analytic/recorder.py`, `TaskModel.context` | consistency replay below |
| 36 of the task's 38 weighted reward terms | `analytic/task.py` (`r_*`) | `analytic_check`: max error <= 3.4e-4 per term (most 1e-7) |
| Five failure margins | `TaskModel.margins` | max 2e-3 (the deliberate acos clamp at upright) |
| 110-D actor observation | `TaskModel.clean_obs` + recorded corruption | exact at recorded states |
| Physical world model | `analytic/world_model.py` | 8-step held-out error ~1 cm / 0.009 rad after 30 iterations at 6144 envs |
| BPTT, critic, replay | `analytic/learner.py`, `trainer_analytic.py` | consistency replay; compiled/eager gradient cosine 0.99998 |

`undesired_contacts` and `joint_acc` cannot be written from kinematics; their
real values are recorded and enter imagination as a per-step correction
`real - analytic(real state)`. The PD-torque term is analytic but approximate
(MuJoCo reports the last substep's torque); the same correction makes it exact
at recorded states.

### Recorded instants inside one `env.step`

physics -> terminations -> **rewards** (`s_end`, context) -> resets ->
**command update** (`s_cmd`: the racket state the command caches for the next
step) -> interval push -> observations (`s_start = s_cmd + push`).
Racket rewards therefore read `s_cmd` and `robot.data` rewards read `s_end`, as
in the task. Pushes only change root velocities (checked).

### What is carried inside imagination

The executed q_des (per-episode FIFO delay and sub-tick command latency), the
previous action shown to the actor, HOLD dwell (`HoldDwell` update), racket
state (`s_cmd(t+1) = s_end(t)`) and recorded pushes. Context (clocks,
references, curriculum scales, contact load) follows the recorded tape; a
window stops at a recorded episode end and bootstraps the critic there.

## Validation

1. `analytic_check` at 64 envs, 300 steps, near-zero and noisy (0.8) actions:
   every implemented term matches the real reward manager term to float
   precision; FK matches Warp; observation corruption (noise, latency, mocap) is
   recorded, not modeled.
2. Consistency replay during training: recorded actions through the imagination
   code reproduce the recorded reward (<= 2e-6), executed targets (0) and state
   chain (0).
3. Gradients: eager anomaly detection found one NaN source — `acos`/`asin` at
   exactly +-1 in the task's `readiness_ratios`/`rpy`, multiplied by a zero
   `amax` gradient — fixed with clamped local copies (values identical away from
   the singularity). Compiled backward graphs produced `0 * inf` (eager PyTorch
   masks it) in every update; gradients are made finite at the compiled
   boundary and agree with eager to cosine 0.99998 on the same batch.
4. Speed (6144 envs): eager imagination was 4.7 s per update (kernel-launch
   bound, independent of batch size); compiled 1.2 s; iteration ~2.2 s; device
   memory ~10.4 GiB.

5. Full-size runs: 30 iterations with actor updates from iteration 4 trained
   without skipped (non-finite) steps. A 2000-iteration validation run was
   stopped at iteration ~200 (still world-model-only) so the user could start
   the long run; by then the 8-step held-out world-model error was 5 mm and
   0.009 rad. An earlier attempt failed with CUDA OOM only because
   `debug_compare_gradients` re-ran imagination eagerly at full batch; it now
   uses a 256-row sub-batch.

    Reading the paper (arXiv 2610.28480, section 3.1 and 3.3): the return uses
    a soft survival weight c_{t+1} = c_t (1 - d_t) with d a learned (BCE)
    termination probability; there is no explicit termination cost, and the
    whole long-range survival incentive is the loss of future reward through
    c_t and the critic bootstrap c_H V(s_H), whose gradient flows into the
    actor. Imagination is fully on-policy inside the model for H steps: a
    recorded episode end never cuts a rollout.

    Our analytic termination is sigmoid(margin / 0.05): it carries gradient
    only within 5% of each threshold (2 deg of tilt, 1.25 cm of anchor
    height), so the critic bootstrap was the policy's only long-range
    survival signal. Removing it (scale 0) made the policy blind to the
    anchor-height and tilt terminations until the last step: the base sinks
    toward low balls and the anchor_pos guard (|dz| > 0.25 m) ends the
    episode. Treating recorded terminations as terminal (no bootstrap) is
    also against the paper's semantics: if the current policy avoids the old
    policy's fall in imagination, it should receive the continuation value.
    Both changes are reverted: `bootstrap_grad_scale: 1.0`,
    `bootstrap_at_terminations: true` (the option and `bootstrap_cut` remain
    for experiments). The jitter / HOLD problem of section 12 is therefore
    still open: the horizon bootstrap gradient is noise (cosine 0.05) but
    cannot be dropped. Added `value_path` to `diagnose` (batch-to-batch
    cosine of the critic bootstrap gradient at path lengths 1..32 with and
    without the state path) to tell a jagged critic from a chaotic Jacobian
    chain before choosing the remedy (critic row clip, smoother critic, or
    lambda-weighted bootstraps).

14. Gradient diagnosis at 51300 after reading the paper (2026-10-28,
    `analysis/supermimic_v4/valuepath/`). All numbers are batch-to-batch
    cosines of actor gradients over three 512-row batches unless noted.

    - Critic bootstrap versus path length through the world model
      (`value_path`): 1 step 0.57-0.70, 2 steps 0.46-0.57, 4 steps 0.36-0.40,
      8 steps 0.29-0.44, 16 steps 0.28-0.31, 32 steps 0.18-0.27; gradient
      norm grows about linearly with path length (3.6 -> 42-51). Reward
      terms sit at 0.9+ (full_body_hold 0.99). The critic's one-step
      gradient is usable; the long chain of Jacobians degrades it, and a few
      rows carry most of the norm (section 12: top 1% of rows = 70-88%).
    - TD(lambda) mixtures of the n-step bootstraps (`bootstrap_lambda`):
      H=32: 0.8 -> 0.42, 0.9 -> 0.40, 0.95 -> 0.38 (single horizon 0.27);
      H=16: 0.8 -> 0.48 (single 0.14). Helps, but discounts far rewards by
      lambda^t, so not adopted yet.
    - Horizon 16 instead of 32: no gain (total 0.72 with action clip, reward
      alignment negative). The paper also finds H=32 fastest.
    - Row clipping (`clipping`, total actor gradient): unclipped 0.27;
      action_x4 (training default) 0.78 but cosine with the reward gradient
      0.09 and with the termination gradient 0.08: the update is consistent
      yet almost entirely the critic's direction. critic_x1+action_x4 keeps
      0.79 and raises the reward alignment to 0.24 (norm 14 vs 17.5); x2-x8
      do nothing.
    - Truthfulness (`critic`, 256 rows, 64-step windows, frozen actor after
      H): cosine of the bootstrap gradient with the model's own continuation
      return gradient is 0.47 / 0.39 (0.80 at 17700). Scaling the bootstrap
      gradient: 0 -> 0.24/0.40, 0.25 -> 0.51/0.47, 0.5 -> 0.53/0.48, 1.0 ->
      0.51/0.46 (cosine of the actor gradient with the continuation target).
      The critic's values are right (bias 0.8 on a return std of 11,
      correlation 0.96); its gradient is half right.
    - Termination versus episode-end bootstrap (`signal`, H=16 run with the
      paper's bootstrap-at-every-end semantics): termination |g| 49 cosine
      0.90, episode-end bootstrap |g| 41 cosine 0.92, total |g| 28: the two
      cancel. Mechanism: the critic is fit on post-failure imagined states
      whose margin stays crossed, each step paying the failure cost, so
      V(fallen) = -cost and at the boundary "fail now" (-cost) equals "keep
      the survival weight on a -cost future". Dreamer weights the value loss
      by the cumulative continuation; added `critic_survival_weight`.

    Package under verification (`fix1`, 900 iterations from 51300):
    `critic_survival_weight: true`, `bootstrap_grad_scale: 0.5`,
    `critic_grad_row_clip: 1.0`; everything else as buf400.

16. Jitter: what the numbers say and what others do (2026-10-29).

    Scratch run `2026-10-27_23-35-16_motion_quality_supermimic_v4_scratch`
    (checkpoints 30900-50400 in the user's Gate3 screening): noise-free
    evaluation hold q_des step RMS 20-24 mrad (Gate3 bound 5 mrad),
    reversal rate 17-20 Hz (white noise = 25 Hz at 50 Hz control).
    `sensor_noise_weighted` 0.03 rad^2 = ~31 mrad per joint per tick of
    q_des produced by the observation corruption alone (joint_vel +-0.5,
    gyro +-0.2, mocap 3 mm): the jitter IS the deterministic actor
    amplifying sensor noise. Live training jitter metrics are white noise
    (reversal fraction 0.5) because of the 0.1 collection noise; only the
    noise-free evaluation is meaningful. In the actor gradient the
    smoothness terms are invisible: executed_qdes_rate |g| 0.73 (cos 0.02),
    joint_acc 0, joint_torques 0.64, full_body_quiet 0.38 against the
    critic bootstrap 46-110 with batch cosine 0.3; the sensor-noise penalty
    at coef 20 contributes 20 x 0.03 = 0.6 against an objective of 15.

    External practice (sources in the chat of 2026-10-29):
    - LCP, IROS 2025 (zixuan417/smooth-humanoid-locomotion,
      `rsl_rl/algorithms/ppo_rma.py::_calc_grad_penalty`): lambda *
      E||d log pi(a|o) / d o||^2, lambda 0.002 ramped from 0, on the full
      observation including the 10-step history; action jitter 42 -> 3.2
      versus smoothness rewards 5.7 and low-pass filter 7.9. Their config
      still keeps action_rate -0.1, dof_acc -2.5e-7, torques -1e-5.
    - CAPS, ICRA 2021: temporal ||pi(s_t) - pi(s_t+1)||^2 + spatial
      ||pi(s) - pi(s + eps)||^2, eps ~ N(0, sigma = expected sensor noise).
      Our `sensor_noise` penalty is CAPS-spatial with the true corruption
      model; we have no direct temporal term (only the reward head).
    - BeyondMimic / mjlab tracking: action_rate_l2 -0.1 only; joint_vel
      noise +-0.5 like ours; last action in the observation.
    - SuperMimic paper: ||a_t - a_t-1||^2 at -0.1 (tracking) / -0.3
      (locomotion), computed on the imagined actions themselves.
    - HuB 2025: action rate -1.5, dof vel -1e-3, dof acc -3e-6, torque
      -2.5e-5; Ornstein-Uhlenbeck IMU noise; pushes every 1 s; 25-step
      history; control delay 20-60 ms and PD gains +-25% randomised.
      Removing the IMU noise raised action change 5-10x.
    - PAVE, ICML 2026 oral (AIRLABkhu/PAVE): policy Lipschitz constant
      <= ||d^2Q/dsda|| / action curvature; regularise the critic's action
      gradient field (consistency under state noise and across consecutive
      states, curvature floor). Matches our diagnosis that the actor
      gradient is 92% critic direction with heavy-tailed rows.

    Plan (learner side, no task code): (a) raise `sensor_noise_coef` until
    it binds (200-500) with an LCP-style ramp, and evaluate it on the
    imagined observations along the horizon rather than obs0 only;
    (b) add the SuperMimic/CAPS temporal term sum_t ||a_t - a_t-1||^2 on
    the imagined actions directly in the objective (weight ~0.1 on
    normalised actions); (c) later, a PAVE-style consistency term on
    grad_a V between consecutive imagined states (`critic_grad_row_clip`
    is the crude version). Not: deploy-side filters (contract forbids
    `qdes_rate_limiter`; worst in LCP's table).
